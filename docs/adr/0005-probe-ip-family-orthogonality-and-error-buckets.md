# 探测地址族与 DNS 记录类型正交及单栈错误分桶语义

`ProbeTask` 的 `ip_family`（`AUTO` / `IPV4` / `IPV6`）仅作用于 `ICMP`、`TCP` 与 `HTTP` 任务；`DNS` 任务禁止设置 `ip_family`，改用独立的 `dns_record_type`（`A` / `AAAA`）。当节点本机缺乏任务所需地址族通往公网的路由时（按该族对公网地址做 UDP connect 能否取得源地址判定，不以接口上是否挂有地址为准——内网网桥如 docker0 的私有地址不代表具备该族），Agent 按周期正常上报 `ProbeError` 而非静默跳过，同时告警引擎将整分钟均为错误的桶（`sent == errors`）视为无可达性读数，既不触发也不恢复丢包告警；部分错误的分钟以 `lost / (sent − errors)` 计丢包率，探测错误不进分母。

DNS 探测中连向解析器的传输协议栈已由 `dns_server` 字面量唯一决定，与所查询的记录类型正交（经 IPv4 解析器查 `AAAA` 或经 IPv6 解析器查 `A` 均属合法场景），混用同一字段会造成语义冲突。在单栈节点上持续上报 `ProbeError` 延续了 `ICMP unavailable` 的可见性原则，避免与任务未下发或调度停滞混淆；同时修正全错误桶不算出 `0%` 丢包率，防止本机网卡失地址把正在触发的丢包告警误判为恢复。
